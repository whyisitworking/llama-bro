# Retrieval on our own docs

How well `llamabro-rag` finds the passage that answers a question, measured on this repository's documentation. The
result is F191 ([findings](../../../docs/research/findings.md#f191)); it set (or kept) the defaults of `Chunker` and
`search`.

## The corpus

Read at run time from the working tree: `docs/*.md`, `docs/research/findings.md` and `docs/design/*.md` (15 files,
about 1.09 million characters on 2026-11-26). Each file is one `Document` whose id is its path from the repo's root.

## The questions

[`questions.jsonl`](questions.jsonl): 47 questions written by hand from reading the docs, not generated by a model. One
JSON object per line:

- `question`: as a person would ask it, mostly not in the docs' own words;
- `doc`: the file the answer is in;
- `answer_span`: a quote of about 5-20 words from that file, verbatim and on one line, which holds the answer.

The spread: 12 on `docs/architecture.md`, 14 on `docs/decisions.md`, 14 on `docs/research/findings.md` and 7 on
`docs/testing.md`. They mix exact names (`closeAndJoin`, `memoryReserveMib`, `LB_CONTRACT_PORT`), IDs ("which decision
made DFlash an opt-in?"), numbers (16 384 tokens, 50.25 MiB, exit code 77) and paraphrases ("why are idle models never
put to sleep?"). Every span occurs exactly once in its file when written; the eval fails if a span is no longer there
(a doc was rewritten), and then the question's span is updated by hand.

## The measure

A question is found at k when one of the top k passages comes from its document and overlaps its span: the passage's
`[start, end)` and the span's position in the file (its first occurrence) share at least one character. Recall at k is
the share of questions found at k. Recall at 5 is the headline; recall at 1 comes free from the same lists.

The grid, all on bge-small (F16, mean pooling, no query or passage prefix: `EmbeddingFormat.of` gives `None` for it):

- chunk size: `Chunker(maxTokens = 128, 256, 512, overlap = 0.15f)`, counted by bge-small's own tokenizer
  (`TokenCounter.Model`). Each size's library is built once and every mode searches it;
- mode: dense only (the query's vector against every passage, top 5), BM25 only (top 5), hybrid (`Library.search`:
  dense and BM25 top 50 each, reciprocal rank fusion with k = 60, limit 5) and hybrid with rerank (`search` with
  jina-reranker-tiny F16 over the fused top 20, limit 5).

No multilingual embedder was in the test models folder, so none was compared; the corpus is English anyway.

With 47 questions one question is 2.1 points of recall. Differences of one or two questions are noise.

## Running it

It needs the host build (`sdk/scripts/check.sh --only build`) and the small test models
(`sdk/scripts/fetch-test-models.sh`). It is not one of check.sh's steps: it measures, it gates nothing.

```bash
./gradlew -p sdk :llamabro-rag:testDebugUnitTest --tests 'com.suhel.llamabro.rag.HostRagEvalTest' --rerun-tasks -i \
    -Pllamabro.host.lib="$PWD/sdk/native/build/host/bin" \
    -Pllamabro.host.models="${LB_TEST_MODELS_DIR:-$HOME/Downloads/llamabro-test}"
```

It prints the table (chunk size, passages, index time, mode, recall at 1 and 5, milliseconds per query), every question
missed at 5 with the runs that missed it, and the total time. Without the two properties the test is skipped. A run
took 455 s on a Mac's CPU (F191): about 120 s to build each size's index, since each embeds the whole corpus once,
and about 90 s for the reranked queries.
