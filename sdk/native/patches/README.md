# llama.cpp patches

The SDK never edits the llama.cpp submodule. Every change to it is a patch here, applied in name order to a build copy
(`sdk/native/build/llama.cpp`) by `sdk/native/scripts/prepare-llama.sh`, which Gradle's `prepareLlama` task runs before
every native build. A patch that no longer applies stops the build. Each speed patch must have won an A/B on the phone
([D10](../../../docs/decisions.md)); a functional patch, such as `0003`, is checked by tests instead.

| Patch | Origin | Why | Evidence | Drop when |
|---|---|---|---|---|
| `0001-hexagon-gdn-long-batch.patch` | Ours; one line, the change to propose upstream ([upstream-notes.md](../../../research/ph/delta-net/upstream-notes.md)), nothing posted | NPU prefill with MTP: Hexagon's fast chunked delta-net kernel was gated on K = 1, so with MTP (K = 4) prompts fell to the slow recurrent kernel. The gate also accepts `n_tokens > K`, where ggml's contract only promises slot 0 (`ggml.h`), as CUDA's chunked kernel already does. +61% at b12352, as fast as the head/tail split it replaced, and drifts less than upstream's own MTP on/off; applies unchanged at b12479, where it gives +67% (F163) | F7, F8, F121, F149, F163, D80 | Upstream's gate accepts `n_tokens > K` (`htp-kparams.cpp`, `K == 1`), or GDN replay (PR #31669, +114% on the phone, F149) is on by default in the pin; re-measure at every upgrade |
| `0002-bf16-neon-vec-dot.patch` | Upstream PR [#30432](https://github.com/ggml-org/llama.cpp/pull/30432) (head `cde3115c`), unmerged at b12479 (2026-11-17) | ggml-cpu has no ARM path for BF16 dot products (issue [#29917](https://github.com/ggml-org/llama.cpp/issues/29917)); the CPU image encoder with a BF16 projector 16.5 s → 3.1 s | F123, F127 | #30432, or another ARM BF16 path, is in the pinned build |
| `0003-load-progress-stop-hook.patch` | Ours; written up as reference for upstream ([upstream-pr.md](../../../research/ph/load-cancel/upstream-pr.md)), nothing posted | A cancelled load can't stop reading weights: llama-server's load progress callback always says go on. The patch adds `server_context::set_load_abort_callback`, asked before the 200 ms throttle, for the text model, the draft and the image encoder ([D67](../../../docs/decisions.md)). Ported to b12479's server refactor without a change in behaviour: the same three load stages call the same callback (F163). Stages without a progress call (context creation, warm-up, kernel compile) can't be stopped, though with an mmproj or a draft a cancel during the text model's is caught at the next stage's first tick (`server-context.cpp` ~1315-1404 at b12479, patched). Functional, not speed: no A/B; checked by the `load_stops_*` native tests and the phone timing | F145, F163 | Upstream has an equivalent hook (or its progress callback lets an embedder stop the load) |
| `0004-hybrid-swa-checkpoint-restore.patch` | Ours; upstream issue and PR drafted (`research/ph/cache-stop/`), nothing posted | On the LFM3 family (hybrid with SWA layers, `sliding_window: 256`), llama-server reuses the live slot state or a checkpoint only if its `pos_min` is n_swa - 2 before the shared prefix's end, but there `pos_min` is the recurrent position, equal to the state's end. So neither the live state nor the checkpoint 4 tokens before the previous prompt's end is ever reused: each turn re-processes the whole last user message, its audio encoded again (F152), or the whole chat while messages are short. The patch applies the SWA threshold only to partly removable memory (the fix tested on upstream master). Since b12479 the threshold lives in `server_prompt::get_reuse` (`server-slot-sched.cpp`), unchanged, and the patch passes it the SWA window only when `seq_rm_type == PART`, else 0; otherwise the state must end before the first token to evaluate, upstream's rule without SWA. Models without SWA layers (LFM2, LFM2.5, Qwen3.5) and with partly removable memory (Llama, Gemma 3) are unchanged. Voice-note chat on the tiny model, turn 4: 811 → 1,206 of 1,237 tokens cached; LFM3-Omni-2B on the Mac CPU, 1,815 → 149 ms. Memory: without the patch fallbacks erased newer checkpoints; with it up to `--ctx-checkpoints` (8) survive per slot, at most 8 x a checkpoint's size more (about +11 MiB on LFM3-Omni-2B, 2.8 MiB each, also per RAM prompt cache entry; a saved slot grew 23.9 -> 36.0 MB), against +32.5 MiB for `--swa-full` (F153). The rule concerns all memory that cannot be partly removed, so DSV4-style compressed caches fall under it too (DSV4 reports n_swa 0, so it is unchanged today). Functional, not speed: no A/B; checked by the `hybrid_swa_cache_*` native tests (cache coverage, short chats and the live state, which fail without the patch; replies equal to an uncached run) and a phone measurement | F153, F163 | Upstream applies the SWA threshold only to partly removable memory (`server_prompt::get_reuse`, `pos_min_thold`) |

Moved to branch `voice/speech-npu` for the voice-mode phase (D90), to be decided again there:
`0005-lfm3a-depthformer-no-cpu-ops.patch`, which kept LFM3-Omni's speech depthformer whole on the NPU (no tiled-weight
view, positions passed in; F155, F156); `0006-tts-skip-text-head.patch`, which added `llama_set_logits` so `/tts` audio
frames skip the text head (F156); `0007-hexagon-poll-noblock.patch`, which polled Hexagon with the no-block read on
Android, so NPU polling stops flooding logcat (F162). The branch also holds the `device-speech` phone step.

Dropped: `0005-hexagon-keep-shared-weights-flat.patch` (F155), which kept any weight read by an op other than a matmul
out of Hexagon's tiled layout. The depthformer patch above (now on `voice/speech-npu`) removes the only such read in the
models we ship, and the keep-flat version sent that matmul to the CPU. It is kept at
`research/ph/speech-output/hexagon-keep-shared-weights-flat.patch` for a model that needs it.

**At every llama.cpp upgrade** (the checklist in [CONTRIBUTING.md](../../../CONTRIBUTING.md#upgrading-llamacpp)), check
each row's "Drop when" first. For a patch from an upstream PR:
`gh pr view <number> --repo ggml-org/llama.cpp --json state,mergeCommit` and, if merged,
`git -C sdk/native/third_party/llama.cpp merge-base --is-ancestor <mergeCommit> HEAD`. If the fix is in the new pin,
delete the patch and its row, and record it in the upgrade's finding. If the PR changed before merging, use the merged
version, not the one carried here.
